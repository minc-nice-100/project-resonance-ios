## Architecture snapshot

**Protocols introduced (4):**
| Protocol | File | Adapters |
|---|---|---|
| `DNSProvider` | `HTTPDNSClient.swift` | `HTTPDNSClient` (prod) |
| `KeyValueStorage` | `KeyValueStorage.swift` | `UserDefaultsStorage` (prod), `InMemoryStorage` (test) |
| `ChatEngine` | `ChatEngine.swift` | `ChatViewModel` (prod) |
| `ModelStore` | `ChatEngine.swift` | `ModelManager` (prod) |

**Remaining architecture notes (from review, not yet addressed):**
- `DNSCache` has no thread synchronization (race condition on `cache` dictionary)
- `MainWebViewController` DNS delegate callbacks fire on background thread — UI work (`loadWebContent`, `showError`) needs `DispatchQueue.main.async`
- `ChatMessageCell.configure(with:)` calls `NSLayoutConstraint.activate` on every reuse, accumulating constraints
- `ModelManager` `paths[0]` force array index
- `WKUIDelegate` missing `runJavaScriptAlertPanel/ConfirmPanel/TextInputPanel`
- `SceneDelegate` uses `UITabBarController` — no `UISplitViewController` for iPad
- No `CONTEXT.md` or `docs/adr/` yet (created lazily by `/domain-modeling`)
